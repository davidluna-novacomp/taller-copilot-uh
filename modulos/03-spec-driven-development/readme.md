# Módulo 3. Spec-Driven Development con GitHub Spec Kit (3 h)

## Objetivo del módulo

Aplicar un flujo basado en especificaciones para mejorar **trazabilidad, claridad y control** antes de delegar la implementación a un asistente o agente de IA.

**Resultado principal:** convertir requisitos en especificaciones y trabajo ejecutable.

## Estrategia de la sesión

| Componente | Aplicación en este módulo |
| :---- | :---- |
| **Concepto breve** | Spec-Driven Development vs. "prompt-to-code"; el flujo constitution → specify → clarify → plan → tasks/analyze → implement. |
| **Demostración guiada** | El instructor recorre el flujo completo del CLI `specify` sobre un requisito simple. |
| **Laboratorio** | Cada estudiante aplica el flujo a la primera funcionalidad del proyecto final. |
| **Discusión técnica** | Diferencias al aplicar el flujo en escenarios greenfield vs. brownfield. |
| **Validación** | Revisar consistencia entre especificación, plan y tareas antes de implementar. |
