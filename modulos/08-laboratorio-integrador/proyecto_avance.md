# Proyecto en avance — Módulo 8: Entrega final end-to-end de TaskFlow

## Qué se construye en este módulo

Una **funcionalidad nueva y completa** de TaskFlow, aplicando el flujo integrador de 10 pasos de principio a fin: Requirement → Spec Kit → Context & Instructions → Agent → Testing → Security → Observability → Pull Request → Code Review → Metrics & Retrospective.

## Tareas a entregar

1. Elegir y definir el requerimiento de la funcionalidad nueva (distinta a "crear y listar tareas").
2. Ejecutar el flujo de Spec Kit completo: constitution (si cambia), specify, clarify, plan, tasks/analyze.
3. Confirmar/actualizar contexto e instrucciones si la funcionalidad lo requiere.
4. Implementar delegando al agente con Plan → Execute → Verify (y MCP si aplica).
5. Escribir y ejecutar pruebas (caso feliz + casos de error/edge cases).
6. Aplicar el checklist de seguridad y gobernanza del Módulo 6.
7. Agregar observabilidad mínima (logging estructurado, métricas, SLI/SLO si aplica).
8. Crear o actualizar el Pull Request correspondiente.
9. Ejecutar revisión asistida por IA + revisión humana final.
10. Documentar la retrospectiva: qué se delegó, qué se verificó, qué evidencia quedó disponible.

## Checklist de aceptación (evaluación del laboratorio integrador)

- [ ] Existe especificación, plan y tareas para la funcionalidad nueva.
- [ ] La implementación fue delegada siguiendo Plan → Execute → Verify, con alcance documentado.
- [ ] Existen pruebas de caso feliz y de al menos 2 casos de error/edge case.
- [ ] El checklist de seguridad/gobernanza fue aplicado.
- [ ] Existe observabilidad mínima verificable (logs/métricas).
- [ ] Existe un Pull Request con la funcionalidad completa.
- [ ] Se documentó una revisión (IA + humana) antes de considerar el PR listo.
- [ ] La retrospectiva final (qué se delegó / qué se verificó / qué evidencia quedó) está documentada.

## Cierre del proyecto final

Con este entregable se completa el recorrido de "TaskFlow" a lo largo de los 8 módulos. El repositorio del proyecto final debería contener, de forma acumulada, el contexto, las instrucciones, los artefactos de Spec Kit, el código implementado, las pruebas, los controles de seguridad y la observabilidad construidos en cada módulo — listo para servir como referencia personal de cómo aplicar GitHub Copilot dentro del SDLC.
